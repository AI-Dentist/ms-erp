## Specs
- S0 Rules (L1): "se consume de lo que hay y si falta se crea respetando la manera en la que se crearon los demás" — MS1 additions are GraphQL, MS3 additions are REST. Additive only: `ejecutarAgenteErp`, Text-to-SQL, existing export URLs and `ReporteGenerativoPayload` consumers keep working. Read-only on business data (the only write is storing the generated report in the existing ReportStore, as agent reports already do). Never build SQL from client strings: entities, columns and filters come from a server-side whitelist; values are bound parameters. No `[skip ci]`.
- S1 Entities (from the approved mobile plan, L2), keys exact:
  `citas` (MS3: "Reservas / Citas"), `pacientes` (MS1), `cuotas` (MS1: "Planes de Pago y Cuotas"), `pagos` (MS1: "Pagos y Recibos" — INGRESO cash movements with their receipt), `egresos` (MS1: "Egresos de Caja Chica" — EGRESO cash movements), `servicios` (MS1: "Catálogo de Servicios (Arancel)"), `insumos` (MS3: "Inventario / Stock de Insumos").
  Each entity exposes every column that is meaningful to a clinic user (no secrets, no internal technical ids beyond the record id). `citas` must include at least: ID Cita, Nombre Paciente, Odontólogo, Fecha y Hora, Estado, Riesgo No-Show. `pagos` must state the payment method and mark QR amounts as nominal (PagoFácil demo charges `/1000`).
- S2 MS1 GraphQL contract (exact names):
  ```graphql
  # Query
  listarEntidadesReporte: [EntidadReporte!]!
  # Mutation
  generarReporteManual(input: ReporteManualInput!): ReporteGenerativoPayload!

  type EntidadReporte { clave: String! nombre: String! origen: String! columnas: [ColumnaReporte!]! filtrosEstado: [String!]! filtroFecha: Boolean! }
  type ColumnaReporte { clave: String! etiqueta: String! tipo: String! }   # tipo: TEXTO | NUMERO | MONEDA_BS | FECHA | FECHA_HORA | BOOLEANO
  input ReporteManualInput { entidad: String! columnas: [String!]! fechaInicio: DateTime fechaFin: DateTime estado: String }
  ```
  `ReporteGenerativoPayload` gains one additive nullable field: `filasTruncadas: Boolean`. `generarReporteManual` fills: `reporteId` (stored in ReportStore so the existing `/api/v1/reports/export/{reporteId}/{pdf|xlsx}` works unchanged), `titulo` (entity + period), `columnas` = the selected column labels in the requested order, `filas` and `filasJson` consistent with each other, `tipoGraficoSugerido` = "TABLA", `resumenAnalitico` = factual row count/period text (no LLM), `consultaSqlEjecutada`/`sqlGenerado` = the parameterized SQL actually executed for MS1 entities, or `MS3 GET /api/agendamiento/reportes/<entidad>` for MS3 entities. Rows capped at 500 (same cap as Text-to-SQL) with `filasTruncadas` true when capped.
  Validation (GraphQL `BAD_REQUEST`, nothing stored): unknown entity, empty columns, unknown or duplicated column, estado not in that entity's `filtrosEstado`, date filter on an entity without `filtroFecha`, fechaInicio after fechaFin, period longer than 366 days.
  Authorization: both operations `ADMIN` only (export is already ADMIN only).
  MS3 entities: MS1 calls the S3 contract forwarding the caller's Bearer token (never a service bypass), base URL from configuration (in Azure the gateway path `/api/agendamiento`); MS1 resolves patient and dentist names from its own catalog. MS3 unreachable / 401 / 403 / malformed -> GraphQL error `SERVICE_UNAVAILABLE`-style message, nothing stored, no partial report.
- S3 MS3 REST contract: `GET /api/agendamiento/reportes/{entidad}?desde=YYYY-MM-DD&hasta=YYYY-MM-DD&estado=...` for `entidad` in `citas`, `insumos` (others -> 404). Middleware `auth.keycloak:ADMIN`. Optional period (both or none; same 422 rules as `/kpis`), `estado` only for citas (MS3 cita states). Response envelope like other MS3 routes: `{"success":true,"data":{"entidad":"citas","columnas":[{"clave":"…","etiqueta":"…","tipo":"…"}],"filas":[{"<clave>":value,…}],"total":N},"timestamp":…}`. `citas` rows include `citaId, pacienteId, odontologoId, consultorioId, fechaHora, duracionMin, tipoTratamiento, estado, reservadaEn, probabilidadNoShow, nivelRiesgo` (risk from the existing ML enrichment; null when the sidecar is unavailable, never invented). `insumos` rows include `insumoId, nombre, unidad (if exists), stockActual, stockMinimo, bajoMinimo, salidasPeriodo`. Read-only.
- S4 Evidence: test-first per rule through public interfaces (GraphQL documents, HTTP routes): every entity happy path with column selection/order, each validation error, cap at 500, ADMIN-only, MS3 failure path (MS1 side with a stubbed MS3), report then exportable through the existing export endpoint as real PDF and XLSX (check file signatures), nothing written to business tables. Full suites green before push; update docs (MS1 schema mirrors + introspection + a docs page; MS3 README). Report commands, exit codes, counts, SHAs, S# covered.
